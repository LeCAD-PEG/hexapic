# Consistency

Two test suites check that one problem gives one answer. The answer must not
depend on the dimension, the orientation or the domain decomposition.

## 2-D and 3-D: `slab3d`

Each case is run as a 2-D case and as a 3-D slab of the same case. The slab
has 8 periodic cells along z. Both are run on one rank and on several ranks,
4 in 2-D and 8 in 3-D. The potential at every node is then compared with the
2-D run on one rank. This covers both field solvers, the walls, objects and
electrodes in both dimensions, and their decompositions.

The first command runs the electrostatic cases, and the second runs one
named case:

```bash
verification/slab3d/slab3d.sh build runs/slab3d
verification/slab3d/slab3d.sh build runs/slab3d plasma_diel
```

The default cases are vacuum geometries solved to the tolerance of the
solvers. They are called `objects`, `ac`, `patch`, `float` and `ywalls`. The
plasma cases `plasma_diel`, `plasma_float` and `plasma_sub` compare the mean
potential over a window of steps. The exit status is the number of cases
that disagree.

## Orientation: `rot3d`

This suite uses one 3-D vacuum geometry. It contains a biased block, a
floating block, a dielectric slab, a partial electrode on a face, a floating
face and a grounded box. The geometry is laid out along x, along y and along
z, and each layout is solved on one rank and on several ranks, 8 by default.
After the axes are swapped back, the potential must equal that of the x
layout.

This test catches errors that a slab cannot show. Examples are the handling
of objects, faces and electrodes along z, and differences between the axes
of the solver.

```bash
verification/rot3d/rot3d.sh build runs/rot3d
```

Both suites need a build with both dimensions, which is the default, and the
Python environment described in [PICMI](../user-guide/picmi.md).
