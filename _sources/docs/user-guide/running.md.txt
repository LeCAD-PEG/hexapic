# Running a case

```text
HEXAPIC case.toml [--set key=value ...] [options]
```

HEXAPIC reads the case, sets it up on the host and then runs the PIC loop on
the GPU. The grid decides the dimension: two cell counts give a 2-D case and
three give a 3-D case.

## Options

| Option | Effect | Default |
|---|---|---|
| `--set key=value` | Change a key of the case for this run. Can be repeated. | |
| `--check` | Read and check the case, set it up on the host, then stop. | |
| `-s N` | Number of time steps. | `[time] steps`, 2000 |
| `-o N` | Write output every N steps. 0 turns the mesh output off. | `[output] every`, 10 |
| `-p N` | Macroparticles per cell for every load. Replaces the weight. | |
| `-d DIR` | Output directory. | `[output] dir`, `output` |
| `-c N` | Write a checkpoint every N steps and at the last step. | `[checkpoint] every`, 0 (off) |
| `-r FILE` | Restart from a checkpoint. | |
| `-h` | Print the help. | |

A relative output directory in the case is relative to the directory of the
case. A directory given with `-d` is relative to the working directory.

## Changing a key: `--set`

`--set` changes a key before the case is read, as if the file contained the
new value. The key is written as a path. Use `[i]` to select the i-th table
in an array of tables:

```bash
build/HEXAPIC case.toml --set time.steps=500 --set 'load[0].density=2e19'
build/HEXAPIC case.toml --set solver.tolerance=1e-6 --set run.init=local
```

The value is written in TOML: a number, `true`, `"a string"` or `[1, 2]`. A
bare word is read as a string. If you set the same key several times, the
last value wins. The changed case goes through the same checks as the file,
and an error message names the `--set` that caused it:

```text
[HEXAPIC] error: --set time.stepz=10:1:5: unknown key time.stepz (did you mean time.steps?)
```

## Checking a case: `--check`

`--check` reads the case with all `--set` changes applied, checks every key,
reads the collision data and builds the particle populations. All of this
happens on the host, and then HEXAPIC stops. No GPU is needed, so you can
check a case on a login node before you submit it:

```bash
build/HEXAPIC case.toml --check
```

```text
[Input] case.toml: ok (3 population(s), 256 x 8 cells)
```

`--check` also warns about a case that is not resolved well: when
$\omega_{pe}\Delta t$ is above 0.2, when a cell is larger than three Debye
lengths, or when a load, beam or source moves its particles more than one
cell in a step. A run prints the same warnings.

`--check` checks the split of the cells for the number of ranks it runs on.
To check a case for 8 ranks, run `mpirun -np 8 build/HEXAPIC case.toml --check`.

An error message gives the file, the line and the column:

```text
[HEXAPIC] error: case.toml:14:9: time.steps: expected an integer
```

## Running on several GPUs

HEXAPIC uses one MPI rank per GPU:

```bash
mpirun -np 8 build/HEXAPIC case.toml
```

HEXAPIC splits the domain into a grid of ranks. It chooses the split from the
number of ranks and the cell counts. On each node, a rank takes the GPU whose
index equals the index of the rank on that node, modulo the number of GPUs.

GPU-aware MPI is not required. Data is transferred through host memory unless
you enable `gpu_aware_mpi` in `[solver.multigrid.tuning]`.

## `hexapic_used.toml`

Every run writes `hexapic_used.toml` into its output directory. This file is
the case as it ran. All `--set` changes and command-line options are applied,
and every key is written out, including the defaults. Comments at the top
list the build options of the binary and the number of ranks. HEXAPIC can
read the file back and gets the same case:

```bash
build/HEXAPIC runs/twostream/output/hexapic_used.toml
```

## Restarting from a checkpoint

With `-c N` or `[checkpoint] every`, HEXAPIC writes a checkpoint every N steps
and at the last step. A checkpoint consists of `checkpoint_<N>.bp` in openPMD
format and one file per rank, `checkpoint_<N>.<rank>`. The file
`checkpoint_<N>.ok` appears when the checkpoint is complete.

The `-r` option restarts a run from a checkpoint and continues at its step.
In this example the first command runs steps 0 to 2000, and the second
resumes at step 1000 and runs to step 4000:

```bash
build/HEXAPIC case.toml -c 1000 -d runs/a
build/HEXAPIC case.toml -d runs/a -r runs/a/checkpoint_1000 -s 4000
```

A restart needs the same grid and the same number of ranks. A build without
openPMD writes only the per-rank files, and so does a case with
`[checkpoint] format = "raw"`.
