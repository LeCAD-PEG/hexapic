# Build options

CMake options decide what the kernels are compiled for: the precision, the
particle shape, the number of dimensions and the GPU back end. Everything
else is set in the case.

The first command below makes a CIC build with the `default` preset. The
second does the same on a cluster:

```bash
cmake --preset default -B build-cic -DHEXAPIC_SHAPE_ORDER=1 && cmake --build build-cic -j
tools/build.sh lumi build-lumi-cic -DHEXAPIC_SHAPE_ORDER=1
```

## The physics

| Option | Default | Meaning |
|---|---|---|
| `HEXAPIC_REAL_TYPE` | `float` | Precision of the particle and field data, `float` or `double` |
| `HEXAPIC_MG_REAL_TYPE` | `double` | Precision inside the multigrid solver, `double` or `float` |
| `HEXAPIC_SHAPE_ORDER` | `2` | Particle shape. `1` is CIC (linear), `2` is TSC (quadratic). |
| `HEXAPIC_DIMS` | `2;3` | Particle loops to build: `2` (2D3V), `3` (3D3V) or both |

The field solver computes in `HEXAPIC_MG_REAL_TYPE` and converts the data at
its interface. Its precision is therefore independent of the precision of the
particles. With `float` data, a solver tolerance below `1e-5` cannot be
reached.

Building a single dimension with `-DHEXAPIC_DIMS=2` or `-DHEXAPIC_DIMS=3`
takes about half the time.

## Build requirements of a case

A case that needs a certain precision or shape states it in
[`[build]`](case-toml.md#build). A binary that was built differently refuses
to run the case. A case without `[build]` runs on any build. The
`hexapic_used.toml` of each run records the options the binary was built
with.

```toml
[build]
shape_order = 1
```

## The back end and the libraries

| Option | Default | Meaning |
|---|---|---|
| `HEXAPIC_GPU_BACKEND` | `AUTO` | `AUTO`, `CUDA`, `HIP` or `SYCL` |
| `CMAKE_CUDA_ARCHITECTURES` | `native` in the `default` preset | NVIDIA architecture, for example `80` (A100) or `90` (H100) |
| `HEXAPIC_USE_OPENPMD` | `ON` | openPMD output through ADIOS2. `OFF` gives a smaller build without it. |
| `HEXAPIC_USE_HYPRE` | `OFF` | HYPRE as a second Poisson solver for A/B checks. CUDA only. |

## The kernels

These options change how the kernels work but not what they compute. The
defaults are the tuned values.

| Option | Default | Meaning |
|---|---|---|
| `HEXAPIC_CHUNK_SIZE` | `256` | Threads per block, a power of 2 |
| `HEXAPIC_SUPERCELL` | `8` | Edge of a 2-D particle bin in cells |
| `HEXAPIC_SC_3D` | `4` | Edge of a 3-D particle bin in cells |
| `HEXAPIC_BIN_SLACK` | `1` | Lazy re-binning. With `1` a particle may stay in its bin until it is more than one cell outside. `0` keeps the bins strict. |
| `HEXAPIC_PUSH_ETILE` | `ON` | The push gathers E from a per-bin tile in shared memory |
| `HEXAPIC_PUSH_PREFETCH` | `OFF` | The push loads the particles of the next chunk ahead of time |
| `HEXAPIC_BIN_BLOCK_FEW` | `0` | Block size of the push on a grid with few bins. `0` means 1024. |
| `HEXAPIC_PUSH_ROLL3` | `3` | Loop layout of the 3-D push over the z planes |
| `HEXAPIC_PUSH_STAGE3` | `8` | Number of leaving particles a 3-D push block can stage, in sixteenths of its threads |
| `HEXAPIC_GMG3D_VREAL` | `float` | Precision of the V-cycle in the 3-D multigrid, `float` or `double` |
