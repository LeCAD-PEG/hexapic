# Output

A run writes into its output directory. By default this is `output` next to
the case. You can change it with `[output] dir` or with `-d`.

| File | Written | Contents |
|---|---|---|
| `hexapic.bp` | every `[output] every` steps | The openPMD series |
| `hexapic_used.toml` | at the start | The case as it ran, see [Running a case](running.md) |
| `checkpoint_<N>.*` | every `[checkpoint] every` steps | Checkpoints, see [Restarting from a checkpoint](running.md#restarting-from-a-checkpoint) |
| `live/` | with `[output] live` | Frames for the [viewer](../visualization/live.md) |
| `counts.txt` | with `[output] counts_every` | Particle counts per species |
| `xprof_<step>.<rank>` | with `[output] x_profiles` | Profiles along x |
| `xprof_avg.<rank>` | with `x_profile_average` | Mean of the profiles over the output steps |
| `wall_phi.bin` | with `[output] wall_potential` | Potential of the lower x wall after every solve |
| `performance.jsonl` | with `[output] performance` | Timing of the step on every rank, see [Performance](#performance) |

`[output] from` delays the mesh output, the profiles, the counts and the
fluxes until the given step.

## The openPMD series

`hexapic.bp` is an [openPMD](https://www.openpmd.org) series written with
ADIOS2 in the BP5 format. Each rank writes its own part of the domain
directly into the series, so no data is gathered on one rank. Every output
step is one iteration with these meshes:

| Mesh | Location | Unit | Contents |
|---|---|---|---|
| `phi` | nodes | V | Potential |
| `rho` | nodes | C m⁻³ | Charge density |
| `Ex`, `Ey`, in 3-D also `Ez` | nodes | V m⁻¹ | Electric field |
| `Bx`, `By`, `Bz` | nodes | T | Magnetic field |
| `<species>_density` | cells | m⁻³ | Number density |
| `<species>_Vx`, `_Vy`, `_Vz` | cells | m s⁻¹ | Mean velocity |
| `<species>_T` | cells | eV | Temperature |
| `<species>_phase_<a>_v<c>` | 256 × 512 bins | counts | Phase space |

The magnetic field is written only when the case has a `[magnetic_field]`.
The field is static, so it is written once, at the first output step, and
carries the attribute `static`.

The phase spaces are histograms of a position axis `a` against a velocity
component `c`. The axis is x or y, and in 3-D also z. The component is x, y
or z. They are written when `[output] phase_space` is on.

The particles are written at the first step. With `[output] final_particles`
they are also written at the last step. Each macroparticle has a `position`,
`momentum`, `weighting`, `charge` and `mass`.

Any openPMD reader can open the series. This example uses
[openPMD-api](https://openpmd-api.readthedocs.io). The array it loads has the
shape `(ny + 1, nx + 1)`, so the first index is y:

```python
import openpmd_api as io

series = io.Series("runs/twostream/output/hexapic.bp", io.Access.read_only)
it = series.iterations[2000]
phi = it.meshes["phi"][io.Mesh_Record_Component.SCALAR].load_chunk()
series.flush()
print(phi.shape)
```

A build without openPMD (`-DHEXAPIC_USE_OPENPMD=OFF`) writes no series.

## Performance

With `[output] performance = true`, HEXAPIC samples one step every
`performance_every` steps on every rank. The default is every 10 steps. Rank
0 appends one line per sample to `performance.jsonl`. A sample contains the
following.

- The device time of each phase of the step. The phases are the field, the
  solve alone, and, summed over the species, the push with its deposit, the
  packing of migrants, the sources and the insert, the arrivals, the heat
  sources and the collisions. The field phase covers the seam exchange of the
  charge, the solve and the computation of E. The arrival time is the time a
  queue waits for the host to exchange the migrants. These times come from
  timing events on the GPU queues. They are read one sample later, so
  sampling does not hold up the step.
- The host time per step since the last sample, for the whole step, the seam
  exchanges, the solve and the migration. The migration time covers the wait
  for the packs and the MPI rounds.
- The number of particles of each species, and the migrants sent and received
  per step.
- The MPI traffic per step. This includes the time in point-to-point waits
  and in collectives, the number of collective calls, the bytes sent, and the
  bytes and messages sent to each peer. The traffic is counted through the
  MPI profiling interface. The file `io/mpi_traffic.cpp` wraps `MPI_Isend`,
  `MPI_Waitall`, `MPI_Allreduce` and others, so the halo exchanges and
  reductions of the solvers are included.
- The timeline of the step, with the start and end of each phase on its
  queue. Times are in milliseconds from the start of the field phase.

Each line holds the minimum, mean and maximum of every metric over the ranks,
and the rank that has the maximum. At output steps the line holds the values,
the timeline and the links of every rank instead. The first line of the file
names the metrics and the bars of the timeline. It also lists the cells and
the device of each rank, with its host, name, index and memory.

```text
{"hexapic_performance": 2, "ranks": 4, "every": 20, "dim": 2, "metrics": [...], "boxes": [[0, 0, 128, 128], ...],
 "devices": [{"host": "node01", "device": "NVIDIA A100-PCIE-40GB", "index": 0, "local": 0, "memory": 4.24e10}, ...],
 "bars": [{"name": "field", "lane": "field"}, {"name": "push", "lane": "electrons"}, ...]}
{"step": 1980, "wall": 80.1, "v": [[38.8, 38.8, 38.8, 3], ...]}
{"step": 1500, "ranks": [[38.8, ...], ...], "bars": [[0, 36.0, ...], ...], "links": [[[1, 136992, 40.2], ...], ...]}
```

The [Performance panel](../visualization/views.md#performance) of the viewer
displays this file. On one A100 the sampling costs less than 1 % of the run
time.

## Diagnostics at the end of a run

With `[output] wall_flux`, the run prints the particle flux and the energy
flux of each species into every wall.

`[output] energy_budget` adds an energy budget for each species. It splits
the change in kinetic energy into the contributions of Coulomb collisions,
MCC, heating, emitted particles, the walls and the push. The push
contribution is the work done by the field.
