A running simulation#

With [output] live = true, HEXAPIC writes the frames for the viewer itself. It writes them at the output steps into <output>/live/, from a separate thread. You can start the viewer before or after the run:

build/HEXAPIC case.toml --set output.live=true -d out &
python tools/viz/hexapic_viz.py out

Following the run#

While the run is going, the server serves the frames in out/live. If neither live frames nor a series exist yet, it waits for them. The app checks for new steps every 2 s and shows the latest step while it follows the run. When you select a step by hand, the app stops following. To resume, press End or click follow the last step on the status card.

The ● LIVE indicator blinks while the run is going. Hover over it to see the status card, or click it to keep the card open. The card shows:

  • the fraction of the run that is done, and the current step out of all steps

  • how long the run has been going, and its rate over the last minute

  • the time left, and the clock time at which the run is expected to end

  • the number of frames so far

If the run has reported nothing for 30 s, the card asks whether it has stopped.

The progress comes from rank 0. About once a second it writes <output>/live/progress.json with the current step, the total number of steps, the step the run started from and the seconds since the loop began.

When the run ends#

When the run has ended, the server serves it from the openPMD series. The live frames are the same frames that the server would build from the series, so it reuses them and builds nothing again.

An app that has the run open reloads it by itself as a finished run. It stays at the step it was showing, or goes to the last step if it was following the run. The Performance panel stays open if it was open.

Phase spaces#

The phase spaces are histograms computed on the GPU and summed over the ranks. Their velocity range is set at the first output step. It is widened when particles reach its edge.

Frames between the output steps#

You may want to watch a run more often than the series is written. live_every adds frames between the output steps. live_keep keeps only the most recent of these frames, so that the live directory does not grow.

[output]
every = 5000       # the series, which is the result of the run
live = true
live_every = 200   # a frame every 200 steps for watching
live_keep = 50     # keep the last 50 of the frames in between

Between the output steps HEXAPIC produces only the frame. Nothing is written to the series. The x profiles, the wall fluxes and the energy line of the log are skipped as well.

The timeline then contains the output steps and the most recent frames between them. If a frame is removed while it is displayed, the app shows the next available one. After the run has ended, the viewer shows the series, and the frames between the output steps are no longer available.

Cost of a frame#

A frame costs the run about 4 ms with 2 M particles on one A100 and one rank. A large 3-D run needs more, because the fields and moments are gathered on rank 0. With 160 × 192 × 192 nodes and 0.4 M particles, a frame takes about 0.45 s. For such a run, set live_every to a few hundred steps or more.

A frame of a 3-D run contains two things for each quantity: its three middle planes at full resolution, and its volume. If an axis has more than 128 points, the volume keeps only every k-th point along it, as the 3-D view does. During the run, planes at other positions and profiles over the volume are computed from this volume. After the run they come from the series.
