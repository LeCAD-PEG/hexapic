# `case.toml` reference

A case is a [TOML](https://toml.io) file. The order of its tables does not
matter. All quantities are in SI units unless the name of the key says
otherwise, as in `temperature_eV`, `pressure_Torr` and `angle_to_wall_deg`.

The reader is strict. It stops with an error when a key is unknown, has the
wrong type or is out of range, or when a required key is missing. The error
message names the file, the line and the key. For an unknown key it also
suggests the key you may have meant. A table that does not apply to the case
is an error too. Examples are `[solver.multigrid3d]` in a 2-D case and
`voltage` on a grounded wall.

In the tables below, *required* marks a key that has no default. Positions
and boxes have two entries (x, y) in a 2-D case and three (x, y, z) in a 3-D
case. If you give only two entries in a 3-D case, the box spans the whole z
range.

## The file

| Key | Type | Default | Description |
|---|---|---|---|
| `format_version` | integer | *required* | Version of the file format. Must be `1`. |
| `title` | string | `""` | Short name of the case |
| `description` | string | `""` | Longer description of the case |

## `[grid]`

The mesh is a box with `cells` cells that extends from `lower` to `upper`.
Two cell counts define a 2-D case and three define a 3-D case. The cells must
be square, or cubes in 3-D.

| Key | Type | Default | Description |
|---|---|---|---|
| `cells` | integer array | *required* | Number of cells along x and y, and along z in 3-D |
| `lower` | float array | zeros | Lower corner of the domain [m]. Must be zero. |
| `upper` | float array | *required* | Upper corner of the domain [m] |
| `periodic` | bool array | `false` each | Whether each axis is periodic |

A 2-D case is a slab that is one metre deep in z. Densities are therefore per
cubic metre, and fluxes and currents are per metre of depth.

The mesh starts at the origin, so `lower` must be zero. The positions of the
loads, sources, regions and heating boxes are given from there.

The particles are kept in bins of 8 × 8 cells in 2-D and 4 × 4 × 4 cells in
3-D (the build options `HEXAPIC_SUPERCELL` and `HEXAPIC_SC_3D`). Each rank
holds whole bins. Along each axis the number of cells must therefore be a
multiple of the bin edge times the number of ranks along that axis. HEXAPIC
chooses a process grid that fits. If none fits, it stops and lists the
multiples that each process grid needs:

```text
[HEXAPIC] error: [grid] cells = [64, 64] do not split over 3 ranks into whole bins of 8 x 8 cells: the cells must be multiples of, for a process grid px x py, 1 x 3: [8, 24], 3 x 1: [24, 8]
```

A periodic axis has no walls, so a `[[boundary]]` on one of its sides is an
error. A case without any `[[boundary]]` must be periodic in every axis. On
an axis that is not periodic, a side without a `[[boundary]]` is grounded,
and the log says so.

## `[time]`

| Key | Type | Default | Description |
|---|---|---|---|
| `dt` | float | *required* | Time step [s] |
| `steps` | integer | `2000` | Number of time steps. `-s` overrides it. |

## `[run]`

| Key | Type | Default | Description |
|---|---|---|---|
| `seed` | integer | `42` | Seed of all random streams: the initial load, MCC, Coulomb collisions, sources, emission and heating |
| `init` | string | `"replicated"` | How the initial load is drawn. With `replicated` every rank draws all particles. With `local` they are drawn on the device. |

To run an ensemble, run the same case with different seeds. A `[[load]]`
with `same_positions_as` needs `init = "local"`.

## `[[species]]`

Each species has its own table. You define a species either with `particle`,
which sets the mass and the charge, or with `mass` and `charge` directly.

| Key | Type | Default | Description |
|---|---|---|---|
| `name` | string | *required* | Name that loads, boundaries and the output refer to |
| `particle` | string | | `electron` (also `e` or `e-`), `positron` (also `e+`), or an element with its charge state, such as `D`, `D+`, `Ar+` or `W+5` |
| `mass` | float | from `particle` | Mass of a particle [kg] |
| `charge` | float | from `particle` | Charge of a particle [C] |
| `subcycle` | integer | `1` | Push the species every `subcycle` steps, with the time step `subcycle * dt` |

The available elements are H, D, T, He, Li, Be, B, C, N, O, Ne, Ar, Kr, Xe,
Fe, Mo and W. The masses are CODATA 2018 values. For H, D, T and He the mass
of the isotope is used, and for the other elements the standard atomic
weight. The mass of the removed electrons is subtracted.

```toml
[[species]]
name = "electrons"
particle = "electron"

[[species]]
name = "ions"
particle = "Ar+"
subcycle = 10
```

## `[[load]]`

A load creates the initial particles of a species. It fills a box with a
uniform density and a Maxwellian velocity distribution. One species can have
several loads.

| Key | Type | Default | Description |
|---|---|---|---|
| `species` | string | *required* | Species to load |
| `density` | float | *required* | Number density [m⁻³] |
| `temperature_eV` | float | `0` | Isotropic temperature [eV] |
| `thermal_speed` | float array (3) | zeros | Thermal speeds $\sqrt{T/m}$ along x, y and z [m/s]. Use instead of `temperature_eV`. |
| `drift` | float array (3) | zeros | Drift velocity [m/s] |
| `weight` | float | | Physical particles per macroparticle |
| `macroparticles_per_cell` | integer | | Macroparticles per cell of the box. This sets the weight. |
| `region` | table | the domain | Box to load, `{ lower = [...], upper = [...] }` [m] |
| `same_positions_as` | string | | Name of another species. The particles are placed at the positions of its load, which gives a charge-neutral start. Needs `[run] init = "local"`. |

Give either `weight` or `macroparticles_per_cell`, but not both. If you give
neither, the run needs the `-p` option.

```toml
[[load]]
species = "electrons"
density = 1e16
temperature_eV = 2.0
macroparticles_per_cell = 64
region = { lower = [0.0, 0.0], upper = [0.01, 0.02] }
```

## `[magnetic_field]`

A static external magnetic field. Without this table there is no magnetic
field. The key `type` is required and selects one of three kinds of field:

| `type` | Field |
|---|---|
| `uniform` | The same field everywhere, given as a vector or as a magnitude with an angle |
| `profile` | A field that varies along one axis |
| `radial` | A field that points away from a line, as in a Hall thruster |

### `type = "uniform"`

Give either `vector`, or `magnitude` together with one of the two angles. The
angles lie in the x–z plane and assume walls that are normal to x.

| Key | Type | Default | Description |
|---|---|---|---|
| `vector` | float array (3) | | $\mathbf{B}$ [T] |
| `magnitude` | float | | $\lvert\mathbf{B}\rvert$ [T] |
| `angle_to_wall_deg` | float | | Angle between the field and the wall surface [deg]. At 90 the field points along x. |
| `angle_to_normal_deg` | float | | Angle between the field and x, the wall normal [deg] |
| `bit1_rotation` | bool | `false` | Rotate the charged species as BIT1 does. Needs `magnitude` and an angle. |

### `type = "profile"`

The field at each node depends on the coordinate of the node along `axis`.
It is interpolated linearly between the given positions and stays constant
beyond the first and the last. The particles gather $\mathbf{B}$ from the
nodes in the same way as $\mathbf{E}$.

| Key | Type | Default | Description |
|---|---|---|---|
| `axis` | string | *required* | Axis along which $\mathbf{B}$ varies: `x` or `y`, in 3-D also `z` |
| `position` | float array | *required* | Positions along the axis, in increasing order [m] |
| `vector` | array of float arrays (3) | *required* | $\mathbf{B}$ at each position [T] |

This example is the radial field of a Hall thruster in an axial–azimuthal
case. The field points out of the x–y plane and peaks at x = 7.5 mm:

```toml
[magnetic_field]
type = "profile"
axis = "x"
position = [0.0, 0.0075, 0.025]
vector = [[0.0, 0.0, 0.006], [0.0, 0.0, 0.010], [0.0, 0.0, 0.001]]
```

### `type = "radial"`

The field is $\mathbf{B} = B_r\,\hat{\mathbf{r}}$, where $\hat{\mathbf{r}}$
points away from a line along `axis`. You give $B_r$ at the radius `radius`
for several positions along the axis. Between the positions it is
interpolated linearly, and beyond them it stays constant.

Outside the radius `core`, $B_r$ falls off as $1/r$, which keeps
$\nabla\cdot\mathbf{B} = 0$. Inside `core` it is proportional to $r$ and
reaches zero on the line.

| Key | Type | Default | Description |
|---|---|---|---|
| `axis` | string | *required* | Axis of the line: `x` or `y`, in 3-D also `z` |
| `center` | float array | *required* | Position of the line in the other axes, in order [m] |
| `position` | float array | *required* | Positions along the axis, in increasing order [m] |
| `magnitude` | float array | *required* | $B_r$ at `radius` for each position [T] |
| `radius` | float | *required* | Radius at which `magnitude` is given [m] |
| `core` | float | `radius / 2` | Radius inside which $B_r \propto r$ [m] |

## `[[boundary]]`

A wall sets a condition for the field and decides what happens to the
particles that reach it. A wall is either a whole side of the domain, given
with `location`, or a straight segment of nodes, given with `segment`.

| Key | Type | Default | Description |
|---|---|---|---|
| `type` | string | *required* | Type of the wall, see the next table |
| `location` | string | | A whole side: `x_lo`, `x_hi`, `y_lo` or `y_hi`, in 3-D also `z_lo` or `z_hi` |
| `segment` | table | | A segment of nodes, used instead of `location`: `{ from = [j, k], to = [j, k] }`. In 3-D it is a rectangle with `[j, k, l]`. |
| `name` | string | `""` | Name used in the output |

| `type` | Field | Particles |
|---|---|---|
| `grounded` | $\phi = 0$ | absorbed |
| `biased` | $\phi = V + A \sin(2\pi f t + \varphi)$ | absorbed |
| `floating` | the potential that follows from the collected charge | absorbed, charge collected |
| `dielectric` | an insulating surface: its collected charge enters the field, or $\partial\phi/\partial n = 0$ | absorbed, charge collected |
| `open` | $\phi = 0$ | removed |
| `reflective` | $\partial\phi/\partial n = 0$ | reflected |

Some types have keys of their own:

| Key | Type | Default | Wall type | Description |
|---|---|---|---|---|
| `voltage` | float | `0` | `biased` | DC potential $V$ [V] |
| `amplitude` | float | `0` | `biased` | AC amplitude $A$ [V] |
| `frequency` | float | `0` | `biased` | AC frequency $f$ [Hz] |
| `phase` | float | `0` | `biased` | AC phase $\varphi$ [rad] |
| `group` | integer | own | `floating` | Walls with the same group share one potential |
| `permittivity` | float | `1` | `dielectric` | Relative permittivity |
| `charge_accumulating` | bool | `true` | `dielectric` | With `true` the charge that the wall collects stays on it as a surface charge. With `false` the charge is discarded and the wall has $\partial\phi/\partial n = 0$. |

If two biased walls share a corner node, the voltage of the wall that is
defined later applies there.

A `reflective` wall covers a whole side. A `floating` or `dielectric` wall
can cover part of a side. The rest of that side is then grounded.

### `[[boundary.surface]]`

A surface process makes a wall emit particles in response to the particles
it absorbs. It describes secondary electron emission. It also describes
recycling, where an ion that reaches the wall returns as a neutral with the
energy `energy_eV`. A wall can have several surface processes, and the walls
together at most 16.

| Key | Type | Default | Description |
|---|---|---|---|
| `process` | string | *required* | Must be `emission` |
| `yield` | float | *required* | Particles emitted per absorbed particle. A value below 1 is a probability. The yield times the ratio of the two weights must be at most 16. |
| `species_out` | string | *required* | Species that is emitted |
| `species_in` | string | any | Absorbed species that causes the emission |
| `temperature_eV` | float | `2` | Temperature of the emitted particles [eV] |
| `energy_eV` | float | `0` | If above 0, all particles are emitted with this energy [eV] in a cosine-law direction, and `temperature_eV` is not used |
| `flux_maxwellian` | bool | `false` | Draw the velocities from a flux Maxwellian at `temperature_eV`. This corresponds to `inj_type 0` in BIT1. |

```toml
[[boundary]]
type = "biased"
location = "x_lo"
voltage = -100.0

[[boundary.surface]]
process = "emission"
yield = 0.1
species_in = "ions"
species_out = "electrons"
temperature_eV = 2.0

[[boundary]]
type = "grounded"
location = "x_hi"
```

## `[[region]]`

A region is a solid object inside the domain, either a conductor or a
dielectric. It has the shape of a box. You give the box by its corner nodes
with `nodes`, or by its corners in metres with `box`. Corners in metres are
snapped to the nearest nodes.

| Key | Type | Default | Description |
|---|---|---|---|
| `type` | string | *required* | `conductor` or `dielectric` |
| `nodes` | table | | `{ from = [j, k], to = [j, k] }`, in 3-D with `[j, k, l]` |
| `box` | table | | `{ lower = [x, y], upper = [x, y] }` [m], used instead of `nodes` |
| `name` | string | `""` | Name used in the output |
| `permittivity` | float | `1` | Relative permittivity. For a conductor it applies near its surface and enters its capacitance. |
| `voltage` | float | | For a `conductor`: the potential it is held at [V]. Without this key the conductor floats. |
| `group` | integer | own | For a floating `conductor`: regions with the same group share one potential |
| `charge_accumulating` | bool | `false` | For a `dielectric`: collect the charge that reaches it |

A conductor region is solid, and the particles that reach it are absorbed. A
floating conductor takes the potential that follows from the charge it has
collected. A dielectric region changes the permittivity, and particles pass
through it.

```toml
[[region]]
type = "conductor"
name = "probe"
box = { lower = [0.004, 0.004], upper = [0.006, 0.006] }
```

## `[[beam]]`

A beam injects particles from a segment at a constant current. You give the
segment by its end nodes with `nodes` or by its ends in metres with `box`, in
the same way as for a `[[region]]`.

| Key | Type | Default | Description |
|---|---|---|---|
| `species` | string | *required* | Species to inject |
| `nodes` or `box` | table | | The segment, written as in `[[region]]` |
| `current` | float | *required* | Injection current [A]. In 2-D it is per metre of depth. |
| `weight` | float | *required* | Physical particles per macroparticle. A species with a load, or with another beam or source, has one weight already, and that weight is used. A different value gives a warning. |
| `every` | integer | `1` | Inject every `every` steps. Each injection carries the charge of `every` steps, so the current is the same. |
| `drift` | float array (3) | zeros | Drift velocity [m/s] |
| `temperature_eV` | float | `0` | Temperature [eV]. Use instead of `thermal_speed`. |
| `thermal_speed` | float array (3) | zeros | Thermal speeds along x, y and z [m/s] |
| `normal` | integer | `1` | Direction of the injection along the normal of the segment, `+1` or `-1` |

## `[[collisions]]`

There are two types of collisions. Monte Carlo collisions with a neutral gas
use `type = "mcc"`, with one table per gas. Coulomb collisions use
`type = "coulomb"`, with a single table that lists all pairs. The physics is
described in [Collisions](../implementation/collisions.md).

### `type = "mcc"`

| Key | Type | Default | Description |
|---|---|---|---|
| `gas` | string | *required* | Gas, which selects the cross sections: `H`, `D`, `Ar`, `He`, `N` or `Ne` |
| `pressure_Torr` | float | | Gas pressure [Torr] |
| `pressure` | float | | Gas pressure [Pa]. Use instead of `pressure_Torr`. |
| `temperature_eV` | float | `0.025` | Gas temperature [eV] |
| `electron` | string | *required* | Electron species |
| `ion` | string | *required* | Ion species that ionization produces |
| `ion2` | string | | Species of the doubly charged ions that double ionization produces |
| `neutral` | string | | Species that represents the gas as particles. Without it the gas is a uniform background. |
| `data_dir` | string | built-in | Directory with the cross sections |
| `lxcat_file` | string | | LXCat file with the electron–neutral processes |
| `set` | string | | `bit1` selects the BIT1 data for e + D and D⁺ + D. Needs `gas = "D"` and `neutral`. |
| `scale_electron` | float | `1` | Factor on the electron cross sections |
| `scale_ion` | float | `1` | Factor on the ion cross sections |

Give either `pressure_Torr` or `pressure`. The data are described in
[Collision data](collision-data.md).

The ions must have the weight of the electrons, and so must the doubly
charged ions. With `neutral`, the weight of the neutrals must be at least the
weight of the electrons and of the ions. HEXAPIC stops if a weight does not
fit.

```toml
[[collisions]]
type = "mcc"
gas = "Ar"
pressure_Torr = 0.1
electron = "electrons"
ion = "ions"
```

### `type = "coulomb"`

| Key | Type | Default | Description |
|---|---|---|---|
| `pairs` | array of tables | *required* | The colliding pairs, see the next table |
| `every` | integer | automatic | Collide every `every` steps. Each collision then covers that many time steps. |
| `s_target` | float | `0.1` | For the automatic interval: the largest Nanbu parameter $s$ at the thermal speed per collision |
| `every_max` | integer | `1000` | For the automatic interval: the longest interval [steps] |
| `plasma_period_fraction` | float | `0` | Limit the interval to this fraction of $2\pi/\omega_{pe}$ in the densest bin. 0 means no limit. |

Each entry of `pairs` has these keys:

| Key | Type | Default | Description |
|---|---|---|---|
| `species` | string array (2) | *required* | The two species. Give the same species twice for collisions within a species. |
| `model` | string | | `nanbu` or `ta`. Required for collisions within a species. Between two species only `ta` is available. |
| `log_lambda` | float | `0` | Fixed Coulomb logarithm. With 0 it is computed in each cell as $\ln(\lambda_D / b_0)$. |

A species can collide with at most one other species, and the two species must have the same weight.

```toml
[[collisions]]
type = "coulomb"
pairs = [
  { species = ["electrons", "electrons"], model = "nanbu" },
  { species = ["ions", "ions"], model = "nanbu" },
  { species = ["electrons", "ions"] },
]
```

## `[[source]]`

A volumetric source creates particles in a box. It creates them at a
constant rate. Alternatively, with `balance_wall`, it creates as many as a
wall has collected.

| Key | Type | Default | Description |
|---|---|---|---|
| `species` | string | *required* | Species to create |
| `rate` | float | | Particles created per volume and time, as the mean over the box [m⁻³ s⁻¹] |
| `balance_wall` | string | | A wall, such as `x_lo` or `x_hi`. Used instead of `rate`. See [Balancing a wall](#balancing-a-wall). |
| `region` | table | the domain | The box, `{ lower = [...], upper = [...] }` [m]. With `balance_wall` it may be flat, that is a line or a plane. |
| `weight` | float | from the load of the species | Physical particles per macroparticle. A species with a load, or with another source or beam, has one weight already, and that weight is used. A different value gives a warning. |
| `temperature_eV` | float | `0` | Temperature of the created particles [eV] |
| `thermal_speed` | float array (3) | zeros | Thermal speeds [m/s]. Use instead of `temperature_eV`. |
| `drift` | float array (3) | zeros | Drift velocity [m/s] |
| `shape` | string | `"uniform"` | Profile of the rate along x: `uniform`, `cosine` or `sine` |
| `annulus` | table | | Restrict the particles to a ring around a line along x |
| `same_positions_as` | string | | Name of another species whose source positions are reused |

### Shape, annulus and paired sources

`shape` sets how the rate varies along x inside the region. In the formulas,
$x_0$ is the lower x edge of the region and $L_x$ is its length along x.

| `shape` | Profile |
|---|---|
| `uniform` | Constant |
| `cosine` | $\cos(\tfrac{\pi}{2}(x - x_0)/L_x)$, with its peak at the lower x edge |
| `sine` | $\sin(\pi (x - x_0)/L_x)$, zero at both x edges |

`annulus` creates the particles in a ring around a line along x, within the
x range of the region. It is written as
`{ center = [y, z], inner = r1, outer = r2 }`, with all lengths in metres. In
2-D the centre is `[y]`, and the ring becomes two strips. The region must
contain the ring.

`same_positions_as` names another species. The particles are created at the
positions where the source of that species creates its own particles, which
gives charge-neutral pairs. Both sources must have the same region, shape,
rate and weight, so that they create the same number of particles.

### Balancing a wall

A `balance_wall` source closes the circuit. In each step it looks at the
charge that the wall absorbed in the step before, summed over all species.
It creates that charge again as particles of its own species. For example,
an anode collects electrons and ions, and the difference comes back as
electrons emitted at a cathode. The current through the domain then equals
the current of the wall.

The number of particles to create is rarely a whole number. The source
carries the remainder over to the next step, including a negative one, so
the mean current matches the current of the wall.

At every output step the run prints the current density of each species at
each wall and the number of particles that each balance source emitted. These
lines start with `[Balance]`.

This example is the cathode of a Hall thruster benchmark. It emits electrons
along the line x = 2.4 cm:

```toml
[[source]]
species = "electrons"
balance_wall = "x_lo"
region = { lower = [0.024, 0.0], upper = [0.024, 0.0128] }
temperature_eV = 10.0
```

| Key | Type | Default | Description |
|---|---|---|---|
| `species` | string | *required* | Species to heat |
| `model` | string | *required* | `resample` redraws the velocities. `bit1` is the collisional heating of BIT1. |
| `region` | table | the domain | Box that is heated [m] |

## `[smoothing]`

Before every field solve, the charge density is smoothed with passes of the
1-2-1 filter along each axis.

| Key | Type | Default | Description |
|---|---|---|---|
| `x_passes` | integer | `1` | Number of passes along x. 0 turns the smoothing along x off. |
| `y_passes` | integer | `1` | Number of passes along y |
| `z_passes` | integer | `1` | Number of passes along z, in 3-D |

## `[solver]`

These keys control the Poisson solve. The method is described in
[Solvers](../solvers/index.md).

| Key | Type | Default | Description |
|---|---|---|---|
| `type` | string | `"auto"` | `auto` picks `strip` for a 2-D case that is a strip (see below) and `multigrid` otherwise, and prints its choice and the reason. `multigrid` uses GMGa3 in 2-D and GMG3D in 3-D. `strip` is the direct solve of a 2-D strip. `hypre` is available in 2-D in a build with HYPRE and is meant for A/B checks. |
| `tolerance` | float | `1e-5` | Relative residual at which the solve stops. With `float` data it cannot be below `1e-5`. |
| `phi_extrapolation` | bool | `true` | Start each solve from an extrapolation of the last two solutions |
| `zero_line_x` | float | | Position x of a line that is held at 0 V [m] |
| `strip_check` | integer | `0` | `strip`: compare the first this many solves with a multigrid solve to 1e-12, and print the largest difference and both residuals |
| `strip_exchange` | string | `"pcr"` | `strip`: the values at the rank boundaries by `pcr` (cyclic reduction, messages between ranks) or `gather` (to one rank and back) |
| `strip_overlap` | string | `"auto"` | `strip`: exchange those values while the GPU runs the sweeps (`on`), after them (`off`), or time both on the first solve and keep the faster (`auto`) |

`strip` solves the Poisson equation of a 2-D strip directly, in one pass
without iterations: a scrape-off layer from divertor to divertor, for example.
The case needs Dirichlet walls at both x ends (grounded or biased), y walls
that are reflective, grounded or periodic, a uniform permittivity and nothing
inside the domain. The ranks split the strip along x only. Across y the
operator is diagonalised once; along x every mode is a tridiagonal system.
Each rank solves its part, and the values at the rank boundaries come from a
small system per mode that the ranks solve together. `auto` takes `strip`
when the case meets these conditions, its cells split into whole bins on
P x 1 ranks, and it has at most 128 cells across y: above that the multigrid
is faster. In every other case `auto` takes `multigrid`.

`zero_line_x` holds a line in the plasma at 0 V, where otherwise the upper x
wall would be at 0 V. The solver first computes the solution $U$ with the
potentials of the walls. It then subtracts a ramp in x:

$$
\phi = U - \frac{x - x_0}{x_l - x_0}\,\bar U(x_l) .
$$

Here $x_0$ is the lower x end of the domain, $x_l$ is the position of the
line, and $\bar U(x_l)$ is the mean of $U$ over the line, that is over y and
in 3-D also over z. The ramp is zero at the lower x end, and the mean
potential on the line becomes 0. The potential of the upper x wall then
floats. Charoy et al. hold their cathode line in this way
{cite:p}`charoy2019`.

### `[solver.multigrid]` (2-D)

The solver decides every key that you leave unset. It either times the
options at setup or uses its built-in value, which is shown in parentheses.

| Key | Type | Default | Description |
|---|---|---|---|
| `autotune` | bool | `true` | Time the depth of the hierarchy, the bottom solve and the fused threshold at setup |
| `smoother_autotune` | bool | `true` | Also time the smoother settings `omega` and `sweeps` |
| `autotune_exhaustive` | bool | `false` | Run the full depth search for singular operators too |
| `levels` | integer | unset | Depth of the hierarchy. Unset means the full depth or the timed depth. |
| `aggregate` | integer | unset (4) | Cells per rank on the coarsest level before aggregation |
| `bottom_sweeps` | integer | unset (4) | Sweeps on the bottom level |
| `omega` | float | unset (0.8) | Damping of the smoother, between 0 and 2 |
| `sweeps` | integer | unset (2) | Sweeps of the smoother per level |
| `neumann_max_levels` | integer | `0` | Largest depth for singular operators. 0 means no limit. |
| `fuse_nodes` | integer | unset | Levels with at most this many nodes run in one fused kernel. Unset means timed. |
| `stagnation_stop` | bool | `true` | Stop when the residual no longer decreases |
| `stagnation_window` | integer | `16` | Number of iterations over which stagnation is judged |
| `budget_margin` | integer | `1` | Iterations that the asynchronous solve adds to the measured need |
| `fix_fraction` | float | unset | With conductors: cut the hierarchy at the level where the fixed nodes exceed this fraction |

The solver prints every timed choice together with the `--set` option that
fixes it. For runs that must repeat bit for bit, fix these values, or set
`autotune` and `smoother_autotune` to `false`.

Two subtables hold further switches. `[solver.multigrid.tuning]` contains
performance switches that do not change the results.
`[solver.multigrid.debug]` contains older numerics, diagnostics and
self-tests. All their keys and defaults are listed in every
`hexapic_used.toml` and in `source/solvers/multigrid_options.hpp`. These are
the keys you are most likely to need:

| Key | Default | Description |
|---|---|---|
| `tuning.gpu_aware_mpi` | `false` | Use MPI on device buffers, with synchronous exchanges |
| `tuning.communication_avoiding` | `true` | Use the deep-halo cycle on the aggregated levels |
| `debug.verbose` | `false` | Print details of the setup and of the solves |
| `debug.pcg_history` | `false` | Print the residual of every iteration |

### `[solver.multigrid3d]` (3-D)

| Key | Type | Default | Description |
|---|---|---|---|
| `chebyshev_steps` | integer | `2` | Chebyshev steps of the smoother per sweep, from 1 to 8 |
| `chebyshev_low` | float | `1` | Factor on the built-in lower end of the smoother interval |
| `jacobi_omega` | float | `0` | If above 0, use damped-Jacobi sweeps with this weight instead of Chebyshev |
| `bottom_cycles` | integer | `20` | Sweeps on the bottom level when it is not solved by the dense solver |
| `dense_max` | integer | `512` | Solve the bottom level with the dense solver if it has at most this many unknowns. 0 turns the dense solver off. |
| `gather_nodes` | float | `5000` | On several ranks: gather the first level that has at most this many nodes |
| `coarse_cycles` | integer | `1` | Number of V-cycles that solve the gathered level |
| `flexible` | bool | `false` | Use the flexible PCG, with $\beta$ from the last two residuals |

`[solver.multigrid3d.tuning]` and `[solver.multigrid3d.debug]` work as in
2-D. Their keys are listed in `hexapic_used.toml` and in
`source/solvers/multigrid_options.hpp`.

## `[output]`

| Key | Type | Default | Description |
|---|---|---|---|
| `dir` | string | `"output"` | Output directory. A relative path is relative to the case. `-d` overrides it. |
| `every` | integer | `10` | Write the mesh output every `every` steps. 0 turns it off. `-o` overrides it. |
| `from` | integer | `0` | First step with output |
| `final_particles` | bool | `true` | Write the particles at the last step |
| `phase_space` | bool | `true` | Write the phase spaces of each species at the output steps. There is one for each position axis against each velocity component, which gives 6 in 2-D and 9 in 3-D. |
| `live` | bool | `false` | Write frames for the [viewer](../visualization/live.md) at the output steps into `<dir>/live`. A 3-D run writes its middle planes and its volumes. |
| `live_every` | integer | `0` | With `live`: also write a frame every `live_every` steps between the output steps. Nothing goes into the series at these steps. With 0, frames are written at the output steps only. |
| `live_keep` | integer | `0` | With `live`: keep only the last `live_keep` frames between the output steps. The oldest is removed when a new one is written. With 0, all are kept. The frames of the output steps are always kept. |
| `performance` | bool | `false` | Write the timing of the step on every rank into `<dir>/performance.jsonl`. It records the device and host times of the phases, the particles and the migrants, and feeds the Performance panel of the viewer. |
| `performance_every` | integer | `10` | With `performance`: take a sample every `performance_every` steps |
| `frame_bits` | integer | `16` | Bits per value in the frames for the viewer, `16` or `8`. With 8 bits the frames are half the size and have 255 levels. This applies to the live frames and to the frames the viewer builds. The series is always written in full precision. |
| `x_profiles` | bool | `false` | Write profiles along x at the output steps: n, v and T of each species, φ and ρ |
| `x_profile_average` | string | `"none"` | `none`, `window` or `window_and_rows`. `window` writes the mean of the profiles over the output steps. `window_and_rows` also writes the mean for each y row. |
| `x_profile_temperatures` | bool | `false` | Add Tx, Ty, Tz and Txz to the profiles |
| `wall_flux` | bool | `false` | Print the particle and energy fluxes of each species into the walls |
| `energy_budget` | bool | `false` | Print the energy change of each species per operator. Used together with `wall_flux`. |
| `coulomb_probe` | bool | `false` | Add the correlation probe of the Coulomb pairs. Needs `energy_budget`. |
| `counts_every` | integer | `0` | Write the particle counts into `counts.txt` every `counts_every` steps. 0 turns it off. |
| `wall_potential` | bool | `false` | Write the potential of the lower x wall after every solve into `wall_phi.bin` |
| `wall_potential_from` | integer | `from` | With `wall_potential`: first step that is written |

The files that these keys produce are described in [Output](output.md).

## `[tuning]` and `[debug]`

`[tuning]` holds performance switches that do not change the physics.
`[debug]` holds switches for experiments and debugging. The
`hexapic_used.toml` of every run lists all of them with their values.

| Key | Default | Description |
|---|---|---|
| `tuning.push_block` | `0` | Block size of the push: `0` (automatic), `256` or `1024` |
| `tuning.lazy_compact` | `16` | Number of holes per 256 particles at which a bin is compacted. With 0 every push compacts. |
| `tuning.rho_early` | `true` | On one rank: start the field solve as soon as the charge is deposited |
| `tuning.push_split` | on in 3-D | On several ranks: push the bins at the seams first and send their particles while the rest is pushed |
| `tuning.store_slack` | 0.5 in 3-D | Spare room of a bin, as a fraction of its particles |
| `debug.field_off` | `false` | Turn the field off. The charge is zeroed and $E = 0$. Meant for periodic boxes. |
| `debug.field_1d` | `false` | Spread the charge evenly over y, which gives a 1-D field |
| `debug.freeze` | | `all` or the name of a species. The frozen species are pushed with `dt = 0`, so only collisions change their velocities. |
| `debug.poisson_timing` | `false` | Time the field solve on the host. Prints the milliseconds per solve and its share of the step. |
| `debug.profile_steps` | | Profiling window over the steps, `[from, to)` |
