case.toml reference#

A case is a TOML file. The order of its tables does not matter. All quantities are in SI units unless the name of the key says otherwise, as in temperature_eV, pressure_Torr and angle_to_wall_deg.

The reader is strict. It stops with an error when a key is unknown, has the wrong type or is out of range, or when a required key is missing. The error message names the file, the line and the key. For an unknown key it also suggests the key you may have meant. A table that does not apply to the case is an error too. Examples are [solver.multigrid3d] in a 2-D case and voltage on a grounded wall.

In the tables below, required marks a key that has no default. Positions and boxes have two entries (x, y) in a 2-D case and three (x, y, z) in a 3-D case. If you give only two entries in a 3-D case, the box spans the whole z range.

[grid]#

The mesh is a box with cells cells that extends from lower to upper. Two cell counts define a 2-D case and three define a 3-D case. The cells must be square, or cubes in 3-D.

Key

Type

Default

Description

cells

integer array

required

Number of cells along x and y, and along z in 3-D

lower

float array

zeros

Lower corner of the domain [m]. Must be zero.

upper

float array

required

Upper corner of the domain [m]

periodic

bool array

false each

Whether each axis is periodic

A 2-D case is a slab that is one metre deep in z. Densities are therefore per cubic metre, and fluxes and currents are per metre of depth.

The mesh starts at the origin, so lower must be zero. The positions of the loads, sources, regions and heating boxes are given from there.

The particles are kept in bins of 8 × 8 cells in 2-D and 4 × 4 × 4 cells in 3-D (the build options HEXAPIC_SUPERCELL and HEXAPIC_SC_3D). Each rank holds whole bins. Along each axis the number of cells must therefore be a multiple of the bin edge times the number of ranks along that axis. HEXAPIC chooses a process grid that fits. If none fits, it stops and lists the multiples that each process grid needs:

[HEXAPIC] error: [grid] cells = [64, 64] do not split over 3 ranks into whole bins of 8 x 8 cells: the cells must be multiples of, for a process grid px x py, 1 x 3: [8, 24], 3 x 1: [24, 8]

A periodic axis has no walls, so a [[boundary]] on one of its sides is an error. A case without any [[boundary]] must be periodic in every axis. On an axis that is not periodic, a side without a [[boundary]] is grounded, and the log says so.

type = "radial"#

The field is \(\mathbf{B} = B_r\,\hat{\mathbf{r}}\), where \(\hat{\mathbf{r}}\) points away from a line along axis. You give \(B_r\) at the radius radius for several positions along the axis. Between the positions it is interpolated linearly, and beyond them it stays constant.

Outside the radius core, \(B_r\) falls off as \(1/r\), which keeps \(\nabla\cdot\mathbf{B} = 0\). Inside core it is proportional to \(r\) and reaches zero on the line.

Shape, annulus and paired sources#

shape sets how the rate varies along x inside the region. In the formulas, \(x_0\) is the lower x edge of the region and \(L_x\) is its length along x.

shape

Profile

uniform

Constant

cosine

\(\cos(\tfrac{\pi}{2}(x - x_0)/L_x)\), with its peak at the lower x edge

sine

\(\sin(\pi (x - x_0)/L_x)\), zero at both x edges

annulus creates the particles in a ring around a line along x, within the x range of the region. It is written as { center = [y, z], inner = r1, outer = r2 }, with all lengths in metres. In 2-D the centre is [y], and the ring becomes two strips. The region must contain the ring.

same_positions_as names another species. The particles are created at the positions where the source of that species creates its own particles, which gives charge-neutral pairs. Both sources must have the same region, shape, rate and weight, so that they create the same number of particles.

Balancing a wall#

A balance_wall source closes the circuit. In each step it looks at the charge that the wall absorbed in the step before, summed over all species. It creates that charge again as particles of its own species. For example, an anode collects electrons and ions, and the difference comes back as electrons emitted at a cathode. The current through the domain then equals the current of the wall.

The number of particles to create is rarely a whole number. The source carries the remainder over to the next step, including a negative one, so the mean current matches the current of the wall.

At every output step the run prints the current density of each species at each wall and the number of particles that each balance source emitted. These lines start with [Balance].

This example is the cathode of a Hall thruster benchmark. It emits electrons along the line x = 2.4 cm:

[[source]]
species = "electrons"
balance_wall = "x_lo"
region = { lower = [0.024, 0.0], upper = [0.024, 0.0128] }
temperature_eV = 10.0

[solver]#

These keys control the Poisson solve. The method is described in Solvers.

Key

Type

Default

Description

type

string

"auto"

auto picks strip for a 2-D case that is a strip (see below) and multigrid otherwise, and prints its choice and the reason. multigrid uses GMGa3 in 2-D and GMG3D in 3-D. strip is the direct solve of a 2-D strip. hypre is available in 2-D in a build with HYPRE and is meant for A/B checks.

zero_line_x

strip_check

integer

0

strip_exchange

string

"pcr"

strip: the values at the rank boundaries by pcr (cyclic reduction, messages between ranks) or gather (to one rank and back)

strip_overlap

string

"auto"

strip: exchange those values while the GPU runs the sweeps (on), after them (off), or time both on the first solve and keep the faster (auto)

strip solves the Poisson equation of a 2-D strip directly, in one pass without iterations: a scrape-off layer from divertor to divertor, for example. The case needs Dirichlet walls at both x ends (grounded or biased), y walls that are reflective, grounded or periodic, a uniform permittivity and nothing inside the domain. The ranks split the strip along x only. Across y the operator is diagonalised once; along x every mode is a tridiagonal system. Each rank solves its part, and the values at the rank boundaries come from a small system per mode that the ranks solve together. auto takes strip when the case meets these conditions, its cells split into whole bins on P x 1 ranks, and it has at most 128 cells across y: above that the multigrid is faster. In every other case auto takes multigrid.

zero_line_x holds a line in the plasma at 0 V, where otherwise the upper x wall would be at 0 V. The solver first computes the solution \(U\) with the potentials of the walls. It then subtracts a ramp in x:

\[ \phi = U - \frac{x - x_0}{x_l - x_0}\,\bar U(x_l) . \]

Here \(x_0\) is the lower x end of the domain, \(x_l\) is the position of the line, and \(\bar U(x_l)\) is the mean of \(U\) over the line, that is over y and in 3-D also over z. The ramp is zero at the lower x end, and the mean potential on the line becomes 0. The potential of the upper x wall then floats. Charoy et al. hold their cathode line in this way [Charoy and others, 2019].

Type

Default

Description

chebyshev_steps

integer

2

Chebyshev steps of the smoother per sweep, from 1 to 8

chebyshev_low

float

1

Factor on the built-in lower end of the smoother interval

jacobi_omega

float

0

If above 0, use damped-Jacobi sweeps with this weight instead of Chebyshev

bottom_cycles

integer

20

Sweeps on the bottom level when it is not solved by the dense solver

dense_max

integer

512

Solve the bottom level with the dense solver if it has at most this many unknowns. 0 turns the dense solver off.

gather_nodes

float

5000

On several ranks: gather the first level that has at most this many nodes

coarse_cycles

integer

1

Number of V-cycles that solve the gathered level

flexible

bool

false

Use the flexible PCG, with \(\beta\) from the last two residuals

[solver.multigrid3d.tuning] and [solver.multigrid3d.debug] work as in 2-D. Their keys are listed in hexapic_used.toml and in source/solvers/multigrid_options.hpp.

[output]#

Key

Type

Default

Description

dir

string

"output"

Output directory. A relative path is relative to the case. -d overrides it.

every

integer

10

Write the mesh output every every steps. 0 turns it off. -o overrides it.

from

integer

0

First step with output

final_particles

bool

true

Write the particles at the last step

phase_space

bool

true

Write the phase spaces of each species at the output steps. There is one for each position axis against each velocity component, which gives 6 in 2-D and 9 in 3-D.

live

bool

false

Write frames for the viewer at the output steps into <dir>/live. A 3-D run writes its middle planes and its volumes.

live_every

integer

0

With live: also write a frame every live_every steps between the output steps. Nothing goes into the series at these steps. With 0, frames are written at the output steps only.

live_keep

integer

0

With live: keep only the last live_keep frames between the output steps. The oldest is removed when a new one is written. With 0, all are kept. The frames of the output steps are always kept.

performance

bool

false

Write the timing of the step on every rank into <dir>/performance.jsonl. It records the device and host times of the phases, the particles and the migrants, and feeds the Performance panel of the viewer.

performance_every

integer

10

With performance: take a sample every performance_every steps

frame_bits

integer

16

Bits per value in the frames for the viewer, 16 or 8. With 8 bits the frames are half the size and have 255 levels. This applies to the live frames and to the frames the viewer builds. The series is always written in full precision.

x_profiles

bool

false

Write profiles along x at the output steps: n, v and T of each species, φ and ρ

x_profile_average

string

"none"

none, window or window_and_rows. window writes the mean of the profiles over the output steps. window_and_rows also writes the mean for each y row.

x_profile_temperatures

bool

false

Add Tx, Ty, Tz and Txz to the profiles

wall_flux

bool

false

Print the particle and energy fluxes of each species into the walls

energy_budget

bool

false

Print the energy change of each species per operator. Used together with wall_flux.

coulomb_probe

bool

false

Add the correlation probe of the Coulomb pairs. Needs energy_budget.

counts_every

integer

0

Write the particle counts into counts.txt every counts_every steps. 0 turns it off.

wall_potential

bool

false

Write the potential of the lower x wall after every solve into wall_phi.bin

wall_potential_from

integer

from

With wall_potential: first step that is written

The files that these keys produce are described in Output.

[tuning] and [debug]#

[tuning] holds performance switches that do not change the physics. [debug] holds switches for experiments and debugging. The hexapic_used.toml of every run lists all of them with their values.

Key

Default

Description

tuning.push_block

0

Block size of the push: 0 (automatic), 256 or 1024

tuning.lazy_compact

16

Number of holes per 256 particles at which a bin is compacted. With 0 every push compacts.

tuning.rho_early

true

On one rank: start the field solve as soon as the charge is deposited

tuning.push_split

on in 3-D

On several ranks: push the bins at the seams first and send their particles while the rest is pushed

tuning.store_slack

0.5 in 3-D

Spare room of a bin, as a fraction of its particles

debug.field_off

false

Turn the field off. The charge is zeroed and \(E = 0\). Meant for periodic boxes.

debug.field_1d

false

Spread the charge evenly over y, which gives a 1-D field

debug.freeze

all or the name of a species. The frozen species are pushed with dt = 0, so only collisions change their velocities.

debug.poisson_timing

false

Time the field solve on the host. Prints the milliseconds per solve and its share of the step.

debug.profile_steps

Profiling window over the steps, [from, to)
